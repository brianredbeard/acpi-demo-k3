# Managing GRUB menu entries on the K3 board — grubby

The board (192.168.137.146) boots via GRUB2 with BLS (BootLoaderSpec)
entries. `grubby` is the RHEL-native tool for inspecting and changing
them. Hand-editing grub.cfg or fumbling grub2-set-default with the
wrong entry form caused two wrong-boot incidents (2026-11-22; see
docs/fvb-va-bisect-2026-11-22.md). Use grubby.

## Inventory

    grubby --info=ALL          # every entry: title, kernel, initrd, args
    grubby --default-kernel    # which kernel the default resolves to
    grubby --default-title     # the default entry's title

## Setting the default

For BLS-managed kernels (anything with a /boot/loader/entries/*.conf
generated by kernel-install):

    grubby --set-default /boot/vmlinuz-<version>

grubby CANNOT set the default to a custom (non-BLS) menu entry —
e.g. the hand-written gpioy entry in /etc/grub.d/40_custom. For those,
use the grubenv title form (the string must match the menuentry title
exactly):

    grub2-set-default "K3 dbg1 GPIO built-in (EC fix)"
    grub2-editenv list | grep saved    # verify

grub.cfg's generated `set default="${next_entry}"` resolves through
grubenv, so the saved title wins. A literal `set default=` line in
grub.cfg (written by grub2-mkconfig from GRUB_DEFAULT) takes
precedence over saved_entry — check both if boots pick the wrong entry:

    grep -n "set default" /boot/grub2/grub.cfg

## Adding / removing kernels

Kernel RPMs install+remove their BLS entries automatically
(kernel-install hooks: 10-devicetree, 20-grub, 50-depmod,
50-dracut). Removing a kernel package removes its entry. To remove
just an entry (keeping the kernel):

    grubby --remove-kernel /boot/vmlinuz-<version>

NOTE: --remove-kernel removes EVERY entry using that kernel — the
custom k3-* test entries shared the stock kernels, so they had to go
by removing their .conf files from /boot/loader/entries/ (grubby has
no per-title removal for custom BLS files).

## Custom (non-BLS) entries

Live in /etc/grub.d/40_custom; grub2-mkconfig copies them into
grub.cfg after the BLS section. They are invisible to grubby --info.
To change them: edit 40_custom, then:

    grub2-mkconfig -o /boot/grub2/grub.cfg

The board's 40_custom carries exactly one entry now (gpioy recovery);
the archived experiments are in /root/grub-entry-archive/ on the board
(40_custom.full-backup + the removed k3-*.conf files +
removed-files.txt).

## Kernel arguments

    grubby --update-kernel /boot/vmlinuz-<ver> --args="console=ttyS0,115200"
    grubby --update-kernel ALL --remove-args="clk_ignore_unused"

For the custom gpioy entry, args are in the 40_custom menuentry line
(again: edit + mkconfig, not grubby).

## Incident notes

- 2026-11-22 (twice): wrong kernel booted from menu misconfiguration.
  Once from an unprompted 'c' keystroke racing the menu countdown
  (typed at a menu, booted the highlighted entry); once from
  grub2-set-default with a BLS *filename* argument (valid-looking,
  resolves wrong) plus the literal-default precedence above. Both
  recovered via GRUB CLI manual boot (insmod part_gpt/xfs; search
  --fs-uuid; linux+initrd+boot with console=ttyS0,115200).
- The .bak-append initrd (contaminated, iscsi-omission experiments)
  is DELETED; its documentation is in the archive's removed-files.txt.
