## Boot chain and ownership

ROM/SPL, ESOS and OpenSBI execute before edk2. Their loaded addresses, PMP permissions, resident stacks, shared-memory rings, interrupt routing and handoff register values are prerequisites, not proven by edk2 source. Retained ESOS/OpenSBI resources must survive both ExitBootServices and OS memory reclamation. A source DT reservation does not prove that the loaded image occupies that range.

`P/Silicon/Spacemit/Library/SpacemitSecHelperLib/Memory.c:166` imports FDT reserve-map entries as reserved memory and imports reserved-memory nodes; `no-map` regions receive EfiReservedMemoryType, other reserved nodes receive EfiBootServicesData. It publishes discovered RAM resource HOBs and asserts bare SATP during SEC initialization. Inspect the actual incoming/internal FDT, HOBs and final EFI map together. In particular, the reserved-node parser accepts exactly one address/size tuple (`:214`); a future multi-range reserved node would be skipped. It does not validate all integer overflow and malformed-cell cases. These are parser robustness gaps, not demonstrated corruption with the current fixed DT.

`P/Platform/Spacemit/K3/DeviceTree/K3.dtsi:26` contains multiple no-map firmware/shared-memory carveouts. The same file's memory node is an initial description; bootloader/fixup output may differ. For ACPI boot, no OS DT hardware reservation can substitute for an EFI reservation. Non-no-map BootServicesData reservations require a documented reason they become reclaimable at ExitBootServices; firmware-shared queues cannot be silently reclaimed.

`MUSE-Pico.dsc:28` defaults ACPI_ENABLE to FALSE; qualification needs the actual build override. The ACPI branch at `:874` installs AcpiTableDxe, AcpiPlatformDxe, K3 tables and AcpiClockInitDxe; the ordinary FdtDxe branch is excluded there. Internal DT consumption remains legitimate. Inspect the final configuration table to prove the OS does not receive competing hardware descriptions. `PlatformBootManager.c:536` calls EfiBootManagerConnectAll, then `:553` calls PlatformRequireOsDescription. This establishes intended ordering, not success of each device initialization or publication.

`C/UefiCpuPkg/CpuDxeRiscV64/CpuDxe.c` supplies RiscvGetBootHartId and stores FirmwareContext->BootHartId. Validate that the published boot hart is enabled in MADT/RHCT and the OS sees exactly the intended eight X100 harts. A source protocol implementation is not evidence that it dispatched successfully in the final image.

## Runtime dependency review

| ID / priority | Source evidence | Assessment and closure |
|---|---|---|
| RT-01 / high | `P/Silicon/Spacemit/Drivers/Spi/STQspiDxe/QspiDxe.c:141–144` | QspiMmioRemap discards both runtime-MMIO registration statuses. Boot may proceed after an unregistered region; nonidentity runtime access could fault. Fail-injection harness must prove handling before relying on runtime flash. This is a source error-handling finding; actual map failure was not observed. |
| RT-02 / medium | `P/Silicon/Spacemit/Drivers/Spi/SpiNorFlashDxe/SpiNorFlashDxe.c:1254–1260`; `P/Silicon/Spacemit/Include/Protocol/Spi.h:64` | VA-change callback passes the address of embedded SPI_DEVICE as VOID**, although its first members are Cs/Mode/AddrSize scalars, not a pointer. ConvertPointer will interpret those scalar bytes as an address; its return is ignored. Typical unmapped values may simply yield NOT_FOUND rather than corrupting state. Remove this invalid conversion after reviewing all genuine pointer fields; reproduce only in a host/emulator harness. |
| RT-03 / high qualification gap | `P/Silicon/Spacemit/Drivers/FlashFvbDxe/FlashFvbDxe.c:1140`; QSPI callback `:857`; SPI NOR callback `:1245` | Runtime instances and selected callbacks are explicitly converted; FVB maps flash runtime MMIO. This is useful positive evidence, but no nonidentity SetVirtualAddressMap test verifies the complete FVB→SPI NOR→QSPI call graph. Do not count an identity-map boot or GetVariable-only test as runtime-write coverage. |
| RT-04 / medium interoperability gap | `P/Silicon/Spacemit/Spacemit.dsc.inc:88`; `C/EmbeddedPkg/Library/VirtualRealTimeClockLib/VirtualRealTimeClockLib.c:42` | Time services use virtual RTC: persisted epoch plus performance counter, with compilation-time fallback. They do not read the board RTC. GetTime may create NV variables when absent; even a nominal time-read probe can mutate flash. Power-off elapsed time is not established by this implementation. Resolve policy for real time, physical RTC ownership, unsupported services and BRS profile; do not infer a working TAD from an RTC device's existence. |
| RT-05 / conditional profile gap | `P/Silicon/Spacemit/Spacemit.dsc.inc:280,323` | Source sets normal PcdMaxVariableSize to 0x2000 and SMBIOS version to 0x0306. BRS-I minimum SMBIOS is newer; secure-boot variable-capacity rules require auditing effective authenticated-variable limits and build overrides, not assuming the normal-variable limit proves every secure-variable limit. |
| RT-06 / high qualification gap | `P/Silicon/Spacemit/K3/Library/ResetSystemLib/ResetSystemLib.c:28,59,84` | Reset uses SBI SRST with no MMIO, a favorable virtual-address property. Warm reset falls back to cold only on EFI_UNSUPPORTED. Returned terminal requests dead-loop. Reset success, shutdown and persistence depend on deployed SBI and power controller; no watchdog fallback is established here. |
| RT-07 / medium robustness gap | `P/Silicon/Spacemit/Library/MemoryManagementLib/MemoryManagementLibDxe.c`, MapRegAlignmentInternal / MapRegToGcdMmioSpaceInternal | Page rounding and Base+Size arithmetic have no explicit overflow checks. Existing non-MMIO descriptors can be freed/removed before replacement, and failures do not reconstruct prior descriptors. Current fixed ranges do not prove a reachable overflow; use synthetic inputs and injected GCD failures, never malformed board descriptors. |
| RT-08 / high qualification gap | `MUSE-Pico.dsc:85`; `C/EmbeddedPkg/Library/NonCoherentDmaLib/NonCoherentDmaLib.c` | NonCoherentDmaLib supplies map/unmap cache-maintenance paths. This is not evidence every driver calls them correctly, DMA aperture translation is correct, or OS _CCA agrees with hardware. Trace each DMA engine, cache line handling, buffer lifetime, fences and shutdown handoff. |

`P/Silicon/Spacemit/SpacemitDxeFv.fdf.inc:18–23` includes RuntimeDxe, VariableRuntimeDxe, reset, RTC and capsule modules. `MUSE-Pico.dsc:23` defaults real NV mode, while the shared DSC allows emulated NV mode via build define. Verify effective PCDs and flash layout in the build report. Runtime presence in FDF is not a promise that all service calls succeed. The core RuntimeDriverSetVirtualAddressMap implementation in `C/MdeModulePkg/Core/RuntimeDxe/Runtime.c:242` dispatches VA-change handling and relocates runtime state; platform pointer correctness remains the platform's responsibility.

The maintained source's restored _LPI introduces an additional SBI suspend/timer/cache-retention test obligation absent from reconstructed P. The maintained UFS namespace addition introduces enumeration and storage qualification obligations absent from P. Do not merge test outcomes from those two firmware states without hashes of installed AML and full flash images.

## Regression execution contract

`regression.csv` supplies subsystem, procedure, prerequisites, expected result, actual status and evidence. These procedures are planned work, not shell commands executed by this audit. H denotes an instrumented sacrificial K3 with known recovery path and approved maintenance window; E denotes emulator/host harness with disposable firmware/flash snapshots. A virtual machine without K3 devices can test library contracts but cannot qualify K3 silicon.

Before H work, record board revision/SKU, DRAM, boot-media identity, boot-mode switches, firmware/source hashes, kernel/initrd/cmdline, AML hashes, all PCD/build overrides, console capture and upstream/downstream OS differences. Reserve test GUID `9d3f3c17-3d26-4f0e-b69e-7bbf9ccf69db` and variable prefix `K3Audit`; never operate on PK/KEK/db/dbx/BootOrder as scratch state. Use only explicitly provisioned scratch files for positive storage tests. Negative/fault-injection tests, malformed runtime maps, interrupt storms and power-failure flash tests are emulator-only. All current hardware runtime and stress cases are NOT TESTED or BLOCKED; missing harness, binary provenance or hardware access is recorded as BLOCKED.

For every executed case retain raw serial logs, time-stamped command/output, EFI_STATUS/SBI error values, before/after inventories, mapping attributes, interrupts and kernel diagnostics. A pass requires expected results and absence of new exceptions, hangs, checksum differences, ownership violations or unexplained interrupt growth. Never promote source-inspection evidence to a runtime PASS.
