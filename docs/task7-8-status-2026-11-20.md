## Task 7 UFS: HARDWARE-PASS (2026-11-20, v19 cycle)

Final module: ufs-spacemit.ko sha256 de972070087f0313 (three debug
iterations on hardware; see docs/ufs-first-probe-panic.log for the
first-attempt double-put panic).

Iteration log:
1. first fixed module (0f5a941c): core's ufshcd_init_clocks re-resolves
   clki by LIST NAME -> "axi" lookup failed (-ENOENT) — the module
   cannot pre-resolve clocks itself
2. clkdev-alias attempt (94e43499): double clk_put on a freed pointer
   -> kernel panic in ufs_spacemit_acpi_init (both faults at
   __clk_put; SLAB poison address). Fixed by rewriting acpi_init to
   probe-put-alias with NO module-held clk pointers; the CORE acquires
   by alias exactly as in the DT path
3. refclk EALREADY (2e0f240c): "axi" resolved and enabled cleanly,
   "ref" enable returned -EALREADY — the RPMI clock server reports
   RPMI_ERR_ALREADY for enable-when-enabled and the firmware leaves
   ufs_refclk on. Fix: "ref" removed from the ACPI list (firmware-
   managed, fixed rate, only needed for OPP scaling which the ACPI
   path does not use)

Hardware results (v19 + module de972070):
- KINGSTON TY7B-128 (119.3G) enumerated: scsi host0, WLUNs, RPMB
  region 0 registered, /dev/sda with 3 partitions
- 1 GiB direct read: 673 MB/s; 64 MiB direct write: 1.4 GB/s
- write cache enabled, 512K optimal transfer size
- sys1clk TRUTH: zero "clock ... not resolved" warnings — the PA
  link startup timing is driven by the real 491.52 MHz ufs_aclk
- IRQ 135 (APLIC-MSI) delivering: 2591 interrupts during the data
  test
- runtime PM active

Distro-driver note: the stock ufs_spacemit autoloads from the
INITRAMFS at boot (blacklist in /etc/modprobe.d does not reach the
initramfs udev) and fails its probe on the DT reset lookup
(harmless — error only). Swapping in the patched module after boot
works; the clean long-term fix is rebuilding the initramfs without
the stock module or with the patched one installed to /lib/modules.
