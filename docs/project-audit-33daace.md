# K3 release readiness at 33daace

The checked-in EL10-284 recipe cannot reproduce the reported 3l kernel. The EDK2 workflow can also accept an experiment starting from a different firmware baseline and can credit an unused EFI entry with a successful NVMe boot. All three issues can be checked on the host before another board cycle.

## Release blockers

1. **The full kernel RPM selects a UFS patch that produces invalid C.** The patch applies without fuzz to the UFS driver from the pinned BSP carrier (driver Git blob `65aeba393b0f8fac0f2e5ed1d866b56cb68f5704`). In the resulting file, lines 742 and 776 contain `if` statements between functions. The maintained config builds UFS as a module. The separate kmod job uses `k3-ufs-acpi-build5.patch`, which puts both guards inside functions. Use the corrected input in the full spec and compile the resulting UFS object from a fresh RPM preparation. The current spec tests check filenames, presence and ordering. [Full spec](../patches/kernel/el10-284/kernel.spec#L2058) · [Selected patch](history/kernel/rpm/series/el10-284/k3-ufs-acpi.patch#L135) · [Spec tests](../tests/test_kernel_spec_sequence.py)

2. **The documented SRPM staging procedure silently keeps the stock RISC-V config.** The instructions add the series files to the distro sources. The tracked file is named `config-acpidebug`, while Source44 consumes `kernel-riscv64-rhel.config`. In the original 284 SRPM, GPIO and PCIe are modules and rfkill GPIO is disabled. The tracked config builds all three in. With modular PCIe, the built-in K3 MCFG fixups are excluded. Stage the maintained config under Source44's actual name and compare the effective build config before packaging. [Staging instructions](history/kernel/rpm/series/el10-284/README.md#L21) · [Source44](../patches/kernel/el10-284/kernel.spec#L976) · [MCFG conditional](../patches/kernel/el10-284/k3-ecam-segs24.patch#L331)

3. **The flash wrapper accepts a different starting EDK2 image.** Against the archived `pico-acpi-lpi2q-pre/nor-after.bin`, the production installer's offline plan for `pico-acpi-rhct13-f2` returned exactly `['edk2']`. The EDK2 bytes at the baseline offset and length hashed to `fbbcd8a9…`. The baseline sealed in the candidate requires `13024d13…`. The wrapper checks the write list and the readback checks the end state. Both omit the starting EDK2 identity. This permits multiple EDK2 changes in an experiment intended to isolate one. Compare the pre-write bytes with the sealed baseline before confirmation and repeat the check when verifying the receipt. [Flash gate](../edk2_release.py#L265) · [Offline receipt](../edk2_release.py#L209)

4. **Boot qualification can credit an unselected NVMe EFI entry.** A host fixture selected RHEL GRUB on USB with `BootCurrent`, listed another RHEL entry on NVMe, and mounted the Linux root on NVMe. The production evidence checker returned `operator-attested hardware qualification`. It checks the selected RHEL entry, then searches the entire excerpt for GRUB and NVMe. Bind the EFI loader and its device path or partition GUID to the selected entry before recording a successful NVMe boot. [Boot evidence checker](../edk2_release.py#L403)

## Locked ESOS firmware

- **High. CPPC retains a pointer to a local register table.** Registration passes the address of an automatic variable to librpmi. The pinned constructor stores that pointer in `cppcgrp->regs`, and later highest-performance and nominal-frequency reads dereference it. Give the table service lifetime and check register reads after registration has returned. [CPPC register table and registration](../patches/esos/0010-cppc-service-group.patch#L258)
- **High. Two source DT layouts place CPPC fastchannel memory inside an RPMI queue.** The common layout and BS01DCMA override put the 256-byte fastchannel at offset 4096 in the 16 KiB transport. The pinned transport assigns four consecutive 4096-byte queues. CPPC initialization clears that fastchannel range, which occupies the start of queue two. Validate disjoint regions on the effective board DT before registration. Pico overrides its transport base separately. Applying this finding to a deployed Pico requires the actual FIT's DTB. [Common layout](../patches/esos/0010-cppc-service-group.patch#L333) · [Board override](../patches/esos/0010-cppc-service-group.patch#L362)
- **Medium. The ESOS build receipt omits the executable embedded in the FIT.** The retained P2 FIT's decompressed `rcpu0-fw` matched the 273,152-byte build-tree ELF, SHA-256 `5993fa44a671b57a42605fe67ffbd9db5ca71314267074d9333716fccd4e5066`. The receipt records a 267,776-byte `rtthread.bin` with digest `c99d6edc…` and the lite binary. Preserve and hash the ELF in the adapter, then match it to the decompressed FIT payload during packaging. [Build outputs](../build_esos.py#L107) · [P2 packaging record](p2-scoping-2026-11-21.md#L181)
- **Medium. A warm fixture can certify stale ESOS source.** The clock, CCU and ownership tests reuse a directory when its manifest-derived name and a `prepared.json` file exist. Editing patch bytes without updating the lock still exercises the old checkout. Concurrent cold starts can remove another run's in-progress fixture. Validate the current inputs on a cache hit and prepare into a private directory before publishing a shared fixture. The 88-test run below used a fresh directory. [Fixture setup](../tests/test_rpmi_clk_service.py#L37) · [Earlier occurrence](audit-2026-11-20/RECOVERY-AMENDMENT.md#L41)

## Kernel drivers and EDK2 verification

- **High. The rfkill probe can claim the same GPIO twice.** WLEN and BTEN each describe a single shutdown GPIO at resource zero. The patched driver installs the GPS fallback mapping on both PRP0001 devices. On the 284 lookup path, the missing reset property falls back to resource zero. The subsequent exclusive shutdown request then encounters an already claimed line. Limit the fallback to legacy GPS IDs and use the named GPIO for the property-described radios. PCI enumeration alone cannot verify radio control. [rfkill patch](../patches/kernel/el10-284/k3-rfkill-gpio-prp0001.patch#L26) · [Board wiring](rhct12-firmware-acpi-audit-2026-11-22.md#L43)
- **High. The packaged thermal driver lacks the rig's ACPI probe fixes.** The full spec omits the thermal patch. The separate kmod patch adds ACPI zone registration but leaves earlier DT-only property reads and required clock lookups in place. The project records a probe failure before zone registration and describes the fixes applied in the rig. Capture the working driver delta, select it in the intended package paths, and compare the packaged module with the boot record. [Module spec](../patches/kernel/kmods/kmod-k3_tsensor.spec#L18) · [Rig changes](rhct12-firmware-acpi-audit-2026-11-22.md#L262)
- **Medium. Only the DT GPIO probe initializes the bank spinlock.** The ACPI path returns through its own chip registration, then its IRQ callbacks use the lock. The maintained config disables spinlock debugging, which can hide the missing initialization. Initialize the lock once in the shared probe before either chip is registered. [Initialization](../patches/kernel/el10-284/k3-gpio-acpi-v3.patch#L29) · [ACPI return](../patches/kernel/el10-284/k3-gpio-acpi-v3.patch#L479)
- **Medium. The PCIe verifier accepts incorrect AML cache attributes.** It masks the low two bits of the memory descriptor. Bit zero controls writability and bits 2 and 1 encode cacheability. In a host check against the decoded candidate, changing segment 2's flags from `0x1/0x7` to `0x5/0x3` changed both apertures' cache attributes and still passed. Compare the required writability and cacheability fields explicitly. [Memory comparison](../edk2_verify.py#L380)
- **Medium. The documented v8 replay fails with the current PCIe decoder.** The retained `b25849e1` diagnostic manifest records bridge token 24. The verifier requires token 25 and exits with `unexpected PCIe bridge array shape` on FIT `45668dad…`, even with the documented diagnostic options. Bind the decoder to the reviewed ABI for the selected build and exercise both retained layouts. [Token selection](../edk2_verify.py#L37) · [Replay instructions](../README.md#L109)
