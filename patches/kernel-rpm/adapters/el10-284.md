## Rebuild cache discipline

- mock root cache: survives --clean, destroyed by --scrub. Use
  --scrub=all ONLY when the SRPM content changes; --no-clean
  for same-SRPM retries. (Every scrub = ~4min chroot rebuild.)
- The assembled SRPM (~160MB) IS the assembly cache: rebuild
  it only when patches/config/spec change.
- The kernel compile cannot be cached incrementally: %setup
  -q -c clean-creates the builddir (distro design), and the
  local repo carries no ccache rpm (mock's ccache plugin has
  no binary to invoke). A full compile per content change is
  the correct, expected cost.
- Zombie rpmbuild processes hold the buildroot lock and
  poison the next run's logs — kill them via a DETACHED
  script (pkill patterns match ssh's own process group).

## Cycle 15-17 post-mortem (2026-11-22)

- MOCK15/16 (builder) + board MOCK16: all died on
  `k3_gpio_data undeclared` at line 583 — the 284 driver
  defines it at line 669, AFTER our splice point. The struct
  fix (sgb[].base) was verified but this SECOND ordering
  difference bit us only at compile time (patch-apply
  verification cannot catch declaration order).
  Fix: forward-declaration wrapper
  (`static inline k3_gpio_data_fwd() + #define k3_gpio_data`)
  inserted before the ACPI block. SRPM rebuilt + verified
  (2 hits in the SRPM's patch, digest-matched builder/board).
- Lesson: ADAPTER RULE — the splice payload must respect the
  target's DEFINITION ORDER, not just struct layout. Verify
  with a compile, not just git-apply.
- Board-as-builder collision: another operator (console zsh
  session) runs `mock --scrub=all` on the same chroot
  (building ccache + cpp-httplib). Their scrub wiped our
  MOCK17 mid-clean. The board's chroot is SHARED — do not run
  unattended mock there. (Their ccache-in-repo goal is fine
  and would help future kernel cycles.)
- Authoritative build: builder MOCK16 (bg_290 watching the
  gpio gate: fwd-decl presence + .o built + zero errors).

## Iteration-latency rig (2026-11-22, post-v3)

Four single-file failure classes (struct layout, declaration
order, macro capture, escape mangling) each cost 40-60 min of
bootstrap+prep+compile-to-gpio to discover. The rig:

1. **Pre-flight single .o** (builder: ~/k3-tools/
   preflight-gpio.sh): copy the spliced .c into a dead mock
   tree, `make drivers/gpio/gpio-spacemit-k1.o` — 30s gate
   catching all four classes. Only a PASS graduates to SRPM.
2. **Module subset**: `make M=drivers/ufs modules` for the UFS
   patch (module-side; needs Module.symvers from a full build).
   The gpio patch is built-in (=y, the EC fix) so it validates
   only via the single-.o pre-flight.
3. **--no-clean / --short-circuit -bc**: skips the 1.5GB
   re-extract when only %build content changed.
4. **Persistent ccache on the board** (mock config stanza,
   /var/tmp/k3-ccache bind-mounted, 20G, compress): warm
   rebuilds collapse 3-5h -> <1h. Survives --clean/--scrub.
   The builder (4G free) stays the clean authoritative build;
   the board is the iteration machine.

Splice-script discipline: ALL code blocks are Python raw
strings (r""") — a non-raw literal turns "\n" in generated C
into a real newline.

## Cycle 20 post-mortem: UFS patch same class, caught by the rig

MOCK20/21 died at ufs-spacemit.c:742 'expected identifier before
if' — the OLD UFS splice (written against the older driver
revision) glued two fragments at file scope: the DT-reset guard
and the probe ACPI branch belonged INSIDE functions that don't
exist in the 284 BSP driver (its probe is a one-line
ufshcd_pltfrm_init wrapper; the reset lookup lives in
ufs_spacemit_init at line ~449). Rebuilt against the real 284
BSP shape: guard inside ufs_spacemit_init (rst=NULL under
ACPI), branch inside the one-line probe. Second rig catch:
APMU_UFS_RESET_MASK define placement (define-before-use,
splice script hoisting bug).

The rig caught BOTH in seconds (mock --shell + make <file>.o
in the dead tree) instead of 40-60 min cycles. Script-file
discipline: never inline bash -c through two ssh layers —
quote mangling corrupts paths; stage a script file in the
chroot and execute it.
